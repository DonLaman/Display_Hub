      🛠️Genera firmware
      
          
        
          
          Compila il firmware sul server con indirizzo del server già incorporato, pronto
          per il flashing da browser qui sotto. Richiede che la BSP del pannello sia
          presente in firmware/lib/ sul server (vedi README).
        
          

        
        
          
        
          
          WiFi: testa la connessione nel pannello "Test connessione WiFi"
          qui sotto (colleghi il display in USB, cerchi le reti che lui vede da
          dove si trova, provi la password). Se riesce, i campi sotto si riempiono da
          soli: il firmware li userà al primo boot, senza dipendere dalla persistenza
          NVS tra loader e firmware definitivo (si è rivelata inaffidabile in pratica).
          Lasciali vuoti per usare solo il captive portal automatico al primo avvio
          (vedi PROTOCOL.md).
        
          
        
          
          
          

          
        
          

        
          
          
          
            VPN Tailscale: fuori casa (es. sotto l'hotspot del telefono), con la
            VPN accesa, il display raggiunge lo stesso indirizzo LAN qui sopra
            (es. 192.168.1.40) dentro il tunnel, se un tuo subnet router Tailscale pubblica
            quella rete (es. 192.168.1.0/24, approvata nella console). A casa lo raggiunge
            direttamente. Serve solo che le ACL permettano al display di raggiungere la subnet.
          
          
          
          
          
            Compilalo solo se non hai un subnet router per la rete del server e sul
            server è installato Tailscale: verrà usato quando l'indirizzo LAN non è
            raggiungibile né direttamente né tramite una subnet pubblicata.
          
          
          
          
          
          
          
          
          
            Reti WiFi, dispositivi Bluetooth, VPN e server stanno nel file
            displayhub.txt della microSD, modificabile anche dal PC. Senza scheda il
            display usa i valori di questa build e la copia salvata sul server, e le modifiche
            valgono fino al riavvio; la VPN usa la auth key effimera. Si può inserire e togliere
            la scheda a display acceso.
          
          
          
          
            La auth key viene incorporata nel firmware: chiunque abbia il file .bin può
            leggerla. Preferisci chiavi con scadenza breve, oppure inviala dal loader via
            USB (pannello "Test connessione") e lascia vuoto questo campo.
          
          
        
          

        
        
        
        
          
        
          
          Il file generato si chiamerà <wifi|wifi_vpn|usb>-<data>-<versione>[-<revisione>]_<device_id>.bin.
          Il campo Versione parte precompilato con l'ultima versione nota del
          firmware; cambialo solo se stai generando qualcosa di diverso da quello
          attuale.

      🔌Test connessione WiFi (via USB)
      
          
        
          
          1) Genera e flasha uno dei due loader qui sotto. 2) Con il display ancora
          collegato in USB, connettiti a lui da questa pagina. 3) Cerca le reti che
          lui vede da dove si trova e prova una connessione con la password:
          se riesce, le credenziali restano salvate sul device anche dopo aver flashato
          sopra il firmware definitivo.
        
          
        
          
          Leggero: nessuno schermo/touch coinvolto, build più veloce,
          tutto pilotato da questa pagina. Con schermo (WiFi+Bluetooth):
          stesso protocollo (questa pagina funziona identica con entrambi), ma in più
          puoi scegliere la rete e digitare la password direttamente sul display, con
          le Impostazioni (Rete: WiFi, Bluetooth, VPN Tailscale) — utile quando il
          display non è comodamente raggiungibile da un PC. Con questo loader compare
          qui sotto anche la sezione VPN: invii la auth key via USB e
          verifichi che il display entri nella tailnet prima del firmware definitivo.

          Gateway Bluetooth (ESP32 classico)
          
        
          
          Firmware per un ESP32 classico (es. ESP32 DevKit / WROOM-32, non S3): fa da ponte verso una cassa
          Bluetooth (A2DP) e riceve i comandi via WiFi dal display. Dopo il flashing: pannello "USB e loader" per
          collegarlo al WiFi, poi ricerca e connessione della cassa. Vedi Documentazione → Gateway Bluetooth.
        
          
        
          
          
          Compare nelle Impostazioni del display (Gateway Bluetooth) ed e' il nome Bluetooth/mDNS. L'id sul server ne deriva
          ("Gateway Salotto" → gateway-salotto, file data/BT_setting/gateway-salotto.ini): con piu' gateway
          scegli un nome diverso per ciascuno. Vuoto = "DH-Gateway", id gateway-01.

            VPN Tailscale (loader con schermo)
            
            
            
              Chiave e nome restano salvati sul display (NVS) e il firmware "Completo" li
              ritrova, purché il flash non cancelli la memoria. Se dopo il flash la VPN dice
              "Manca la auth key", inseriscila dalle impostazioni sul display o nel form di build.
              La VPN si collega solo con il WiFi connesso.
            
            
            
            
            
            
            
            
            
            
            

            
            
            
              
          
              
        
              
      
              
    
              

    
              
      🌉Ponte USB↔server (modalità USB)
      
              
        
              
          Solo se hai generato il firmware definitivo con "Modalità di comunicazione: USB"
          qui sopra. In quella modalità il display non tocca il WiFi: parla via USB con
          questa pagina, che inoltra le sue richieste al server e rispedisce le
          risposte giù per il cavo. Tieni questa scheda aperta finché il display deve
          restare aggiornato — se la chiudi o disconnetti, il display continua a
          funzionare ma con l'ultimo contenuto ricevuto, finché non riconnetti il ponte.
          Utile ad es. quando il display è collegato a un PC che raggiunge il server solo
          tramite una VPN (Tailscale), mentre il display stesso è su una rete che non ha
          quella rotta (es. hotspot di un telefono).
        
              
        
        
        
        Non connesso
        
              
          Il display che usi per il ponte deve essere una porta USB diversa da
          quella eventualmente già aperta per il test WiFi qui sopra: Web Serial non
          permette due connessioni sulla stessa porta contemporaneamente.

      🗂️Configurazione display e microSD
      
              
        
              
          Il file displayhub.txt di un display: reti WiFi (in ordine di priorità),
          Bluetooth, VPN, server. Lo puoi modificare sulla copia del server (il display
          la riceve al poll successivo), direttamente sul display collegato via USB
          (loader con schermo, o firmware in modalità USB tramite il ponte), oppure preparare un
          file nuovo da copiare sulla microSD.
